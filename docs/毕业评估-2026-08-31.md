# VirtuCoach-Graduate 毕业设计评估（2026-08-31）

> 定位：软件工程专业毕业设计（系统开发 + 应用创新），导师关注“做算法还是做别的”。
> 一句话结论：**系统功能与工程完成度已足够答辩演示；当前最大的缺口不在代码，而在“论文正文 + 定量实验数据 + 可复现/部署材料 + 演示素材”这些毕业交付物。**

## 二、差距清单（按毕业验收优先级）

### P0 —— 论文与答辩材料（最缺，纯代码解决不了）

1. **毕业论文正文不存在**（此前提到的桌面文档未找到）。需产出：摘要/绪论/需求分析/总体设计/详细设计/系统实现/系统测试/总结+参考文献。创新点说明书和项目功能说明可拆解为论文章节素材。
2. **定量实验数据不足**：论文“系统测试”与“实验分析”章节需要数字。已有素材：三套回归测试结果、管理面板的使用意愿/练习趋势/五维数据（可截图+CSV 佐证）。建议补：
   - 各核心指标准确率/召回率（跑测试并记录：和弦检测 3 例、扫弦 5 例、评分 2 例）；
   - 至少 1-2 个“对比/消融”论据（如扫弦排除法→匹配法的误判率对比、和弦证据链有无的差异、LLM 幻觉三防线前后对比）；
   - 用户试用数据（用现有 50 用户种子数据导出统计图表，或真跑几次练习取真实数据）。
3. **图表与截图素材**：架构图、用例图、ER 图、流程图、部署图、各页面截图（`项目功能说明.md` 有截图索引，需补全成独立素材目录，如 `docs/论文素材/`）。
4. **演示脚本**：建议准备 3-5 分钟固定演示路径并写成清单（注册→手机录 HEVC 长视频→上传→报告/回放跳转→聊天→管理面板数据→PWA 安装演示）。

### P1 —— 工程化 / 可复现（答辩前建议补）

5. **依赖清单不完整**：`backend/requirements.txt` 缺 torch/torchaudio、av、chromadb、pytest 等运行时/测试依赖；建议整理完整 requirements + 模型文件清单（bge、hand_landmarker、basic-pitch 权重）+ 下载/放置说明，否则换电脑无法复现。
6. **无 CI / Docker**：GitHub Actions、Dockerfile（api+redis+worker）都在 P1 待办；论文“部署方案”章节需要至少写清楚（未实现也可以写成方案设计+计划）。
7. **密钥安全**：`.env` 已 gitignore；确认 GitHub 仓库无历史密钥残留（主项目 GitLab 曾跟踪过 .env，毕业仓库检查一下）。
8. 小项：pytest 注册 `slow` 标记消除警告；删除 `.pytest_cache`（含 F:\ 旧路径）；`requirements.txt` 移到根目录或注明位置。

### P2 —— 功能缺口（与已有待办一致）

9. P0-2 上传压缩/分片续传（手机大视频，答辩现场最可能踩）。
10. P0-3 任务队列化（当前 `tasks` 为内存 dict，关页面/重启会丢任务；论文“异步任务”设计章节需要它）。
11. P1 Docker 化 + 教师/学生角色 + GitHub CI；P2 数据导出/隐私、公网化、课程内容运营。
12. 内网穿透方案未定（ngrok/NatApp/花生壳，免费版差异见进度同步 3.5）。

### P3 —— 体验细节

13. 移动端建议整体再过一遍 390px（本次只处理了控制台历史；analysis 结果页、admin 表格、对比弹窗等建议逐页检查）。
14. 分析接口本身重（模型推理+LLM），答辩前建议预热模型或准备缓存演示视频，避免现场等太久。
15. PWA 安装说明写进 README（Chrome/Edge 才支持，国产浏览器只有快捷方式）。

## 三、建议的下一步（两周节奏参考）

1. 跑一遍三套回归测试，把结果数字存成 `docs/实验数据.md`（论文测试章节底稿）。
2. 以“创新点说明书 + 项目功能说明”为骨架，搭毕业论文正文目录，先写绪论/需求/设计，再写实现/测试。
3. 补 requirements + 模型清单（可复现），写 `docs/部署说明.md`。
4. 整理截图与图表素材到 `docs/论文素材/`。
5. 功能侧优先 P0-2（上传压缩）与 P0-3（任务队列），各半天-一天可落地。

## 四、结论

**作为毕业项目：功能层面已经“超过合格线、接近优秀线”；作为毕业交付：还差论文正文、数据论证和可复现/演示材料这三件“硬材料”。** 代码与创新点素材齐全，剩下的主要是把已有工作“翻译”成论文语言并补齐证据链。
